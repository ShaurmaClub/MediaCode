# 00. ПРАВИЛА (читать ПЕРВЫМ и перечитывать перед каждой задачей)

Проект: `D:\IMPORTANT\AIProjects\CodexProject\SiteMediaCLI` («МедиаКод», сайт kaiton.ru).
Стек: React 19 + Vite (папка `src/`), Express 5 + SQLite (папка `server/`), тесты `node --test` (папка `tests/`).
Отвечай пользователю ТОЛЬКО на русском языке. Пиши кратко.

## Золотые правила
1. Работаешь ТОЛЬКО по задачам из файлов `01_...md` … `05_...md`, строго по порядку. Одна задача = один коммит.
2. **Никаких `git push`, merge, rebase, reset --hard, checkout main.** Только локальные коммиты.
3. Перед началом создай ветку: `git checkout -b flash/stage-3-4` (если уже есть — `git checkout flash/stage-3-4`).
4. **ЗАПРЕЩЕНО менять** (даже «улучшая»):
   - любую логику внутри `server/routes/*`, `server/lib/shared.js`, `server/app.js`, `server/db.js`, `server/index.js`;
   - структуру базы данных, миграции, файлы `*.db`;
   - `shared/recruitmentTracks.js` (тексты направлений);
   - существующие тесты в `tests/*.test.js` (можно только ДОБАВЛЯТЬ новые файлы);
   - `package.json` зависимости: НЕ ставь новые пакеты, если задача явно этого не просит.
5. Не переписывай файлы целиком. Правь точечно. Не форматируй чужой код, не переименовывай, не «наводи красоту» вне задачи.
6. Не удаляй существующие комментарии, не связанные с твоей правкой.
7. Тексты интерфейса — на русском.

## Обязательная проверка после КАЖДОЙ задачи
Выполни по очереди и убедись, что всё зелёное:
```
npx eslint . --quiet        # ошибок должно быть 0 (предупреждения warning — допустимы)
npm run build               # должно закончиться "built in ..."
npm test                    # "fail 0"
```
Если что-то красное:
- попробуй исправить СВОЮ правку (не тесты!);
- если не получилось за 2 попытки — откати задачу: `git checkout -- .` (и `git clean -fd` ТОЛЬКО для созданных тобой новых файлов этой задачи), запиши в `PROGRESS.md` статус `ПРОВАЛ` с причиной и ПЕРЕХОДИ К СЛЕДУЮЩЕЙ задаче. Не упорствуй.

## Отчётность
После каждой задачи допиши строку в `FLASH_TASKS/PROGRESS.md`:
`| номер | ВЫПОЛНЕНО / ПРОВАЛ / ПРОПУЩЕНО | хэш коммита | что сделано (1 предложение) | что не удалось |`
Файл создай, если его нет (заголовок таблицы: `| № | Статус | Коммит | Что сделано | Проблемы |`).

## Если не уверен — НЕ ДЕЛАЙ
Лучше пропустить пункт и записать вопрос в `PROGRESS.md`, чем сломать. Проверять и исправлять будет старшая модель.
В конце работы выведи пользователю: список задач со статусами и ПОЛНЫЙ список изменённых файлов (`git diff --stat main`).

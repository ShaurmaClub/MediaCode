## 🎯 О проекте

**«МедиаКод»** объединяет два ключевых контура медиацентра колледжа:

1. **Внешний (публичный) портал отбора медиаволонтёров**: позволяет абитуриентам и студентам подать заявку по одному из 6 специализированных направлений, ознакомиться с реальным творческим заданием, прикрепить портфолио и сдать работу с подтверждением согласия на обработку персональных данных.
2. **Внутренняя система управления**:
   - **Кураторы (Сотрудники)** рассматривают поступающие заявки, оценивают работы кандидатов и в один клик создают полноценные учётные записи студентов-волонтёров. Также кураторы создают медиазадачи (фоторепортажи, видеосъёмка, дизайн афиш), назначают исполнителей и начисляют баллы активности.
   - **Студенты-волонтёры** откликаются на задачи, ведут свою электронную зачётную книжку медиаволонтёра и участвуют в общеколледжном рейтинге активности.
   - **Администраторы** управляют учётными записями, производят сброс паролей и контролируют журнал аудита безопасности.

## 🚀 Ключевые возможности

- **Адаптированные формы под каждое направление**: форма подачи заявки кардинально меняется под профиль — от строго 10 JPEG-файлов для фотографа до скачивания исходников для монтажёра и 5-пунктного брифа для SMM.
- **Интуитивный интерфейс куратора**: отображение кандидатов в виде изолированных наглядных карточек с моментальным фильтром по направлениям, статусам и учебным отделениям.
- **Бесшовная конвертация кандидата в студента**: при одобрении заявки куратор генерирует аккаунт с автоматической привязкой отделения, группы, контактов и роли.
- **Журнал аудита действий**: фиксация критических действий (вход, создание задач, начисление баллов, смена статусов, сброс паролей).
- **Сквозная валидация данных**: строгая проверка ФИО на русском языке, нормализация номеров РФ (`+7XXXXXXXXXX`), валидация ссылок и файлов.

## 🎨 6 официальных направлений отбора

Каждое направление имеет уникальные критерии и технические требования к тестовому заданию:

| Направление | Специфика и формат сдачи задания |
| :--- | :--- |
| **Фотография** | **Строго 10 фотографий в формате JPEG**, демонстрирующих репортаж, портрет, композицию, свет и детали. Загружаются непосредственно через форму на сервер. |
| **Видеограф** | **Вертикальное видео 9:16 хронометражем до 1 минуты**. Динамичный ролик о студенческой жизни колледжа. Ссылка на облачный диск (Яндекс Диск, Облако Mail.ru). |
| **Монтажёр** | **Единственное направление со скачиванием исходных материалов**. Кандидат скачивает архив с сырыми видеоматериалами колледжа, делает динамичный ролик и прикрепляет ссылку на готовый результат. |
| **Графический дизайнер** | **Афиша Дня открытых дверей** (Дата: 26 сентября 2026 года, Место: 1-я Мясниковская ул., д. 16, направления IT и креативных индустрий). Ссылка на проект в Figma или облачное хранилище. |
| **SMM** | **Комплексный текстовый бриф из 5 обязательных пунктов**: 1) Инфоповод для абитуриентов; 2) Контент-план на неделю; 3) Идея визуального оформления; 4) Идея короткого клипа (Reels/Shorts/Клипы ВКонтакте); 5) Механика вовлечения аудитории. |
| **Ведущий / корреспондент** | **Вертикальная видеовизитка 9:16 до 1 минуты**. Презентация себя, репортажная подводка о мероприятии колледжа, проверка дикции и работы в кадре. Ссылка на облачный диск. |

## 💻 Стек технологий

- **Клиентская часть (Frontend)**:
  - **React 19** — декларативный пользовательский интерфейс
  - **React Router DOM 7** — клиентская маршрутизация
  - **Vite 8** — высокопроизводительный бандлер и dev-сервер
  - **Lucide React** — современная библиотека пиктограмм
  - **Tailwind-совместимая стилизация** — адаптивная вёрстка, тёмно-синяя брендовая палитра медиацентра
- **Серверная часть (Backend)**:
  - **Node.js** (v20+)
  - **Express 5** — REST API бэкенд
  - **better-sqlite3** — быстрая встроенная реляционная СУБД SQLite с поддержкой WAL-режима
  - **bcryptjs** — надёжное криптографическое хеширование паролей
  - **Zod** — типобезопасная валидация схем запросов
  - **Multer** — безопасная обработка мультипарт-загрузок файлов
  - **Helmet** — установка защитных HTTP-заголовков
  - **express-rate-limit** — защита от перебора паролей и спама
  - **express-session** — защищённые серверные сессии с HttpOnly cookie

## ⚡ Быстрый старт

### 1. Требования к окружению
- **Node.js** версии 20.x или новее.
- **npm** версии 10.x или новее.

### 2. Клонирование и установка зависимостей
```bash
git clone <URL-репозитория>
cd SiteMediaCLI
npm install
```

### 3. Настройка файла переменных окружения
Скопируйте конфигурационный файл из примера:
```bash
cp .env.example .env
```

### 4. Запуск в режиме разработки
Запуск одной командой стартует и Express API (`http://localhost:4000`), и Vite dev-сервер (`http://localhost:5173`):
```bash
npm run dev
```

База данных SQLite (`data/media.db`) создаётся автоматически при первом запуске с предварительно заполненными демо-данными, задачами и тестовыми заявками.

## 🛡️ Ролевая модель и доступ

- **Гость (публичный доступ)**:
  - `GET /` — Главная страница и каталог направлений отбора.
  - `GET /recruitment` — Выбор направления отбора.
  - `GET /recruitment/:trackSlug` — Детальная страница направления с формой тестового задания.
  - `POST /api/public/recruitment/apply/:trackSlug` — Подача заявки с файлами или ссылками.
  - `POST /api/auth/login` — Авторизация зарегистрированных участников.
- **Студент (Student)**:
  - Доступ к разделам биржи задач, деталям задачи, подаче отклика, своей электронной зачётной книжке и таблице лидеров.
  - Защита от прямого доступа к служебным эндпоинтам кураторов (возвращается `403 Forbidden`).
- **Сотрудник / Куратор (Staff)**:
  - Доступ к реестру заявок кандидатов, оценке работ, одобрению кандидатов и автоматической генерации аккаунтов.
  - Доступ к полному жизненному циклу задач (создание, выбор исполнителей, подтверждение выполнения, начисление баллов).
- **Администратор (Admin)**:
  - Управление списком пользователей (редактирование ФИО, группы, отделения, роли).
  - Сброс паролей пользователей.
  - Журнал аудита действий с фильтрацией по типу событий и дате.

## 📱 Модель интеграции с мессенджером MAX

В соответствии с требованиями к пользовательскому опыту реализована лаконичная модель работы с мессенджером MAX:

1. **Без лишних полей и никнеймов**:
   - Кандидат в публичной форме указывает свой российский номер телефона: `+7 (999) 123-45-67`.
   - Для связи через MAX используется простой чекбокс: `[x] Этот номер телефона используется в MAX`.
   - В форме кандидатов нет полей `@username`, так как студенты часто не знают или не имеют никнеймов в мессенджере.
2. **Отображение для куратора**:
   - Если чекбокс отмечен: в карточке куратора отображается понятный статус: `MAX: используется этот номер`.
   - Если чекбокс не отмечен: `MAX: номер не подтверждён как используемый в MAX`.
3. **Архитектурный задел под MAX Mini App и Бота**:
   - В базе данных SQLite сохраняются поля `max_contact`, `max_username` и `max_user_id`.
   - Сервер готов к бесшовному подключению веб-приложения внутри MAX (Mini App) и отправке уведомлений о статусе заявки.

## 🔒 Безопасность и защита персональных данных

1. **Защита от утечек и безопасность репозитория**:
   - Все локальные базы данных (`*.db`, `*.db-shm`, `*.db-wal`), файлы загрузок кандидатов (`uploads/`) и секретные переменные (`.env*`) исключены через `.gitignore`.
   - В кодовой базе отсутствуют жёстко зашитые приватные токены.
2. **Хеширование паролей**:
   - Все пароли хешируются с использованием алгоритма `bcrypt` с солью. Пароли в открытом виде нигде не сохраняются.
3. **Защита сессий**:
   - Cookie сессий настроены с флагами `HttpOnly`, `SameSite=Lax`, предотвращающими кражу через XSS.
4. **Валидация и санитизация данных**:
   - Валидация всех входящих полей через схемы `Zod`.
   - Проверка ФИО: строго русские буквы, пробелы и дефисы (`/^[А-Яа-яЁё\s-]+$/`).
   - Проверка номера телефона: нормализация до стандарта `+7XXXXXXXXXX`.
   - Проверка фотоматериалов: строго 10 файлов с MIME-типами `image/jpeg`.
5. **Согласие на обработку персональных данных**:
   - Подача заявки невозможна без явного согласия кандидата.
   - По клику на ссылку согласия открывается модальное окно с полным текстом политики конфиденциальности в соответствии с законодательством РФ.
   - Дата и факт принятия согласия фиксируются в базе данных (`consent_accepted_at`).

## 🧪 Тестирование и продакшн-сборка

### Запуск интеграционных тестов
Проект покрыт сквозными интеграционными тестами с использованием встроенного тест-раннера Node.js (`node --test`):
```bash
npm test
```
Тесты проверяют:
- Работоспособность эндпоинта `/api/health`
- Авторизацию и обработку некорректных учётных данных
- Пользовательский сценарий студента (задачи, отклик, зачётка, лидерборд)
- Разграничение прав и защиту ролей (`403 Forbidden` для студента на маршруты куратора)
- Сценарий куратора (создание задачи, отбор, начисление баллов, защита от повторного начисления)
- Сценарий администратора (управление пользователями, аудит)
- Полный цикл публичного отбора (получение направлений, валидация полей и форматов файлов, подача заявки, рассмотрение куратором, одобрение и создание аккаунта)
- Готовность эндпоинтов MAX Mini App

### Сборка для публикации
```bash
npm run build
```
Сборка компилирует оптимизированные клиентские ассеты в каталог `dist/`.
